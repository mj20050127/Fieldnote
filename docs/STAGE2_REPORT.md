# 拾问 Fieldnote 第二阶段项目完成报告

项目名称：拾问 Fieldnote 在线问卷系统

阶段主题：独立题库、不可变题目版本、共享复用与跨问卷统计

完成日期：2026 年 10 月 24 日

## 一、项目目标与需求变化

第一阶段已经实现账号会话、问卷草稿、四种题型、条件跳转、回答校验、发布收集、答卷与实时统计。题目完整嵌入问卷，发布后定义固定，历史答案能够按原题位和路径解释。

第二阶段的八项需求要求将常用题目独立保存、在多份问卷中复用、向其他用户共享，并支持修改隔离、版本历史、历史恢复、多版本并存、查看使用问卷以及跨卷统计。直接在原问卷上覆盖题目会改变旧答案的含义，因此本阶段引入独立逻辑题目和不可变内容版本，同时继续保留问卷快照。

确定的规则是：原作者维护原题，接收者可以使用或另存为自己的题；每次保存新增版本，恢复历史也新增版本；已发布问卷不自动升级；跨问卷统计只包含当前用户自己的问卷，不展示其他作者的问卷标题或答卷数据。

八项需求均有对应实现。保存与题库管理由题库页面和创建接口承担；共享由用户名授权与另存承担；修改隔离由不可变版本和快照承担；历史与恢复由父版本、恢复来源和新增版本承担；多版本并存由题位来源中的固定 version_id 承担；使用查询和跨卷统计由本人引用查询与分版本聚合承担。

## 二、系统设计与实施变化

系统继续使用 Python、FastAPI、Pydantic、PyMongo Async、MongoDB，前端使用 Vue 3、TypeScript、Vite 和 Element Plus。本次复用原有身份认证、CSRF、填写组件、跳转引擎、单卷统计与发布流程，没有替换整个系统。

新增 library.py 组织题库权限、版本生命周期与来源校验，library_routes.py 提供接口，library_statistics.py 进行本人跨卷聚合，library_schemas.py 定义请求与响应契约。接口版本升级为 2.0.0，重新导出 OpenAPI 并生成前端类型。

前端侧栏新增“题库”。题库页面支持搜索、题型筛选、分组、归档和恢复；详情提供内容、历史差异、恢复、共享、本人引用问卷与跨卷统计。编辑器新增“保存到题库”“从题库添加”和“更换版本”，沿用当前界面风格。未保存提示、退出保护、请求中的重复操作禁用与手机布局一并接入。

同一道逻辑题目、同一个内容版本和问卷中的题位是三种不同身份。questions[].id 继续是问卷内题位 ID，用于答案、跳转和单卷统计；新增 source.question_id 指向逻辑题目，source.version_id 指向固定内容版本。同题加入一份问卷两次会产生两个题位，但保留相同来源，答案不会覆盖。

导入和换版先修改本地草稿，再通过原有保存流程提交，不会用接口返回值覆盖尚未保存的其他题目、标题和设置。发布后的问卷保持冻结，只允许原有管理操作。

## 三、MongoDB 设计

原有 users、surveys、responses、sessions 四个集合保留，新增 question_banks、questions、question_versions 三个集合。应用启动时重复安装 validator 和索引，不清空业务数据。

question_banks 保存所有者、名称、说明、revision、归档状态及创建更新时间，作为个人分组。题库不内嵌所有题目 ID，以免数组随题量增长。每道自有题目归属一个个人题库，可以移动；收到的共享题通过权限查询集中展示。

questions 保存逻辑题目的所有者、所属题库、shared_with、version_counter、revision、status、archived、derived_from、creation_hash 和时间。派生来源记录原题与版本。共享名单上限为 100 个用户。创建过程使用 creating 状态，首版本成功后激活为 active，未完成题目不进入可用列表。

question_versions 保存 question_id、version_no、parent_version_id、restored_from_version_id、content、created_by、request_id、payload_hash 和创建时间。content 只有题型、题干、说明、选项、必答和校验配置；不保存问卷跳转。版本内容只插入，不提供覆盖或删除 API，历史独立集合避免单文档无限增长。

新增唯一索引为 (question_id, version_no) 和 (created_by, request_id)。题库按所有者查询，题目按所有者、分组和归档状态查询，共享按 shared_with 查询，问卷通过 (owner_id, questions.source.question_id) 反向定位引用。原有用户名、分享码、提交幂等与单次作答索引继续生效。

版本号用单文档原子递增分配，再插入版本；失败可能产生编号空缺，最新版按实际成功插入的最大编号读取。请求编号和内容摘要保证重复请求只得到一个版本，同编号不同内容返回冲突。同父版本的并发保存可以形成两个合法分支，不互相覆盖。

首次创建用用户与请求编号生成确定性题目、版本 ID；若在插入版本前中断，重试继续原创建。恢复旧版复制旧内容并记录恢复来源，仍生成新版本。该设计在现有单机 MongoDB 上运行，不依赖多文档事务。

## 四、复用、共享与历史保护

问卷继续嵌入完整题目快照。填写和提交只读取快照，不依赖题库当前版本、共享是否撤销或题库是否归档。保存 v2 不会修改已发布的 v1 问卷，也不会改写旧答卷或旧统计。

服务端保存来源时检查 version_id 是否属于声明的逻辑题，并逐字段比较快照内容。若客户端修改题干、选项或校验后仍声称引用旧版，则返回 SOURCE_MISMATCH。原引用题位不能直接删除来源以覆盖内容；需要生成新版本、另存新题，或删除原题位后新建独立题位。

共享按规范化用户名解析为用户 ID，授权整个逻辑题目及以后新增的版本。接收者不能写入原题，只能选用版本或另存自己的题，另存后的版本归接收者维护。共享不附带他人问卷、答案或统计的查看权。

撤销授权或归档后，已有问卷及本人历史统计仍可访问，但新增引用、换版、派生需要有效授权和未归档状态。失去授权的历史使用者只能读取自己问卷已经引用的版本，详情和历史列表不会暴露未引用的私有新版。归档保留原题、版本与引用，不进行破坏性删除。

## 五、跳转设计与校验设计

跳转配置继续属于问卷题位。题库版本不携带其他问卷的目标 ID，从题库导入单题时默认 NEXT。草稿换版保留原题位 ID 和跳转规则，不能因新版不兼容而静默清除条件。

发布检查继续验证向后目标、题位唯一性、规则运算符、选项是否存在、必答和校验范围。若新版删除原规则引用的选项、改变题型，或重排删除造成非法目标，服务端定位到题位并阻止发布。已有四种题型、Unicode 码点长度和整数区间可满足性校验继续有效。

前端引用内容只读，跳转可独立配置。“编辑并生成新版本”或“另存为我的题目”完成后，将新来源应用到本地草稿，仍需正常保存并验证。填写时沿用原规则引擎，提交由服务端重新计算路径，拒绝未知、重复和路径之外答案。

## 六、跨问卷统计

统计先按当前账号的 owner_id 过滤引用问卷，再建立各问卷题位到固定版本的映射，最后对相应答卷进行 MongoDB 聚合。界面可按版本及本人问卷筛选，版本历史、引用列表、原始作答与数值频次提供分页。

单选和多选返回各选项次数及有效作答次数，零选择也保留；文本分页查看内容；数字返回有效数、均值、最小、最大和数值频次。不同版本分别返回，避免把题型、单位或选项含义不同的内容混合。

答卷份数、题位机会、到达次数、有效作答次数分别计算。未到达等于题位机会减到达次数，到达未答等于到达减有效作答。同题在同卷出现两次，一份答卷可以产生两次作答，不能表述为两个参与者。

固定核对案例：本人两卷的数值 10、20、30 汇总均值为 20；另一个版本中的 999 不混入。另一案例中，4 次题位机会只有 2 次到达、1 次有效回答，得到未到达 2 次、到达未答 1 次。其他用户的数据不进入这些结果。

## 七、旧数据迁移与备份恢复

升级先固定第一阶段基线并备份，再在独立恢复库预演。迁移脚本默认为 dry-run；正式写入要求 apply、maintenance 和迁移前备份，检查校验和及问卷身份集合。操作者必须先停写；脚本不会自动关闭其他进程。

旧题按问卷 ID 和题位 ID 生成确定性逻辑题与 v1，不按相同题干合并。只补充来源、升级 schema_version 并递增管理 revision，题干、选项、路由、题位 ID、分享码、definition_version、历史答案、访问路径、请求编号和摘要均保留。不完整题目留在原草稿并报告原因。

脚本支持重复执行和中断续跑，检测到并发或内容冲突时保持维护状态检查原因。失败恢复应从迁移前备份恢复到新空库并切换配置，不能只回退代码。备份格式 v2 包含新增三个集合，恢复继续支持第一阶段 v1；sessions 不备份，恢复后重新登录。

本次真实备份有 6 个账号、9 份问卷、6 份答卷。隔离库预演生成 36 道题目和 36 个版本，原快照内容、答卷文档、统计均一致，6 次历史提交全部返回原回执，重复迁移没有重复建题。

正式库在维护窗口完成迁移，8 份有题目的问卷补充 36 个来源，空问卷保持原状。再次执行新增 0 个题目，已有来源 36 个，无跳过或冲突。正式迁移后再次对照备份，原问卷内容和 6 份答卷原文保持一致。备份与原始运行日志留在本机，仓库仅保存不含账号凭据的验收摘要。

## 八、测试结果与问题解决

实施前重新执行第一阶段测试，结果为 61 项后端、5 项浏览器全部通过。实施后完整后端测试为 75 passed，完整 Chromium 测试为 8 passed；Vue 与 TypeScript 检查、生产构建及 OpenAPI 类型生成通过。上游 AnyIO 的弃用提示不影响测试结果。

新增后端测试覆盖题库元数据与权限、不可变历史、并发分支、重复请求、恢复、分享与另存、撤销后历史可见性、来源伪造拒绝、非法跳转阻止发布、分版本统计、单选多选文本分页、故障中断恢复、迁移幂等、旧数据兼容和两种备份格式恢复。校验和损坏的备份在写入恢复库前被拒绝。

新增浏览器测试覆盖题库创建、同卷重复复用、保留未保存问卷标题、发布后快照隔离、草稿换版保留题位、恢复历史、共享及派生、撤销共享和手机未保存保护。原有截止时间、Unicode、分支填写和统计测试继续通过。

遇到的第一个问题是版本号分配后可能在插入前中断。采用允许空缺的原子计数、唯一请求索引和按实际版本读取最新版，并注入故障验证重试不重复。第二个问题是共享撤销容易误伤旧问卷；通过已有快照保留与新增引用授权分开校验解决。

第三个问题是“保存成功”仍被未保存保护误拦截。浏览器测试复现后，保存流程先更新已保存基线并关闭对话框，再触发后续页面跳转。第四个问题是手机历史页并排按钮挤出容器；通过允许换行和消除网格最小宽度约束修正，并补充尺寸检查。

Windows 受限环境曾拒绝 pytest 临时目录访问，恢复测试在正常用户权限下重新执行通过；这项环境问题没有被当成业务通过。最终结果和迁移摘要分别记录在测试报告与 evidence 目录。本报告的测试数字指本地实际执行，远程 CI 结果独立记录，公网部署尚未进行。

## 九、AI 使用过程与交付

在原有 GPT 方案与第一阶段项目基础上，使用 Codex 辅助分析第二阶段需求、设计逻辑题目和不可变版本、编写后端与前端、迁移脚本、测试及文档。使用 Python、PowerShell、npm、pytest、Playwright，并核对 MongoDB 官方版本模式、单文档原子性和事务部署条件。实现后通过真实 MongoDB、浏览器与故障注入核验，修改测试发现的问题。

本次交付包括题库和版本接口、前端页面、迁移与备份工具、生成的 OpenAPI 与类型、后端和浏览器测试、数据库与 API 说明、迁移验收摘要以及本报告。第一阶段代码历史和报告单独保留，第二阶段在独立分支提交；本机备份、环境变量和数据库文件不进入仓库。

最终演示顺序为：创建题目 v1，按用户名共享，多份问卷复用并收集回答，保存 v2 后检查旧卷不变，新草稿明确采用 v2，恢复历史生成新版本，查看本人引用与跨卷统计。
